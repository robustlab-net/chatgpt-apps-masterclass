5.3 Secrets

TMDB 같은 API 키는 GitHub에 커밋·공개하면 안 됩니다. 로컬에서는 .dev.vars, 배포 후에는 Cloudflare Secret을 사용합니다.

정적 파일 env.ASSETS
TMDB 키 env.API_KEY

✅ 체크리스트 — 체크리스트

  1. server/.dev.vars에 API_KEY=값 (일반 env랑 같은 형식)
  2. .gitignore에 .dev.vars* 있는지 확인 (이미 설정됨)
  3. TMDB에서 받은 키 입력
  4. wrangler dev 끄고 → npm run cf-typegen
  5. registerAppTool에서 env.API_KEY 사용
  6. 배포 후: npx wrangler@latest secret put API_KEY (아래 4단계)

1 로컬 — .dev.vars

# server/.dev.vars
API_KEY=여기에_TMDb_API_키_입력

🚨주의: 이 파일은 절대 git commit 하지 마세요. 키가 유출되면 다른 사람이 내 TMDB 할당량을 써버릴 수 있어요.

2 타입 생성 — cf-typegen

env.ASSETS와 동일한 절차입니다. 변수 추가 → wrangler dev 종료 → cf-typegen.

npm run cf-typegen

worker-configuration.d.ts의 Env에 API_KEY: string이 추가되며, IDE에서 env.API_KEY를 인식합니다.

3 Tool에서 쓰기 — registerAppTool

src/index.ts의 TODO 5.1 — 영화 tool을 만들 때 URL에 키를 지정합니다.

registerAppTool(
  server,
  'get-upcoming-movies',
  { /* ... */ },
  async () => {
    const url = `https://api.themoviedb.org/3/movie/upcoming?api_key=${env.API_KEY}`;
    // fetch(url) …
  },
);

fetch(request, env, ctx)에서 받은 env가 tool 콜백 안에서 스코프에 있어야 합니다. 핸들러의 env를 tool 콜백까지 전달하는 패턴을 따릅니다. 문제 시 Inspector로 tool이 호출되는지 디렉터리를 확인하세요.

4 배포(프로덕션) — wrangler secret put

로컬 .dev.vars는 내 컴퓨터에서만 적용됩니다. npm run deploy로 올린 Worker에는 그 파일이 업로드되지 않습니다. 그래서 Cloudflare에 Secret을 따로 등록합니다.

🏠 로컬 (wrangler dev)

.dev.vars → env.API_KEY

☁️ 배포된 Worker

secret put API_KEY → env.API_KEY

server 폴더에서 실행하세요. Wrangler 로그인이 되어 있어야 합니다.

npx wrangler@latest secret put API_KEY

이렇게 하면 어떻게 되나요? — 터미널에서 일어나는 일을 순서대로 보면 흐름을 파악하기 쉽습니다.

  1. Wrangler가 이름이 API_KEY인 Secret을 Cloudflare 계정(이 Worker)에 등록합니다.
  2. 터미널에 값 입력 프롬프트가 가 표시됩니다 → TMDB API 키를 붙여넣고 Enter (입력한 글자는 화면에 다시 에코 없이 저장됩니다).
  3. 키는 Cloudflare 암호화된 저장소에만 들어갑니다. wrangler.jsonc, Git, 배포 파일 어디에도 평문으로 포함되지 않습니다.
  4. 이미 배포된 Worker가 있으면 보통 몇 초 안에 반영됩니다. 코드에서는 여전히 env.API_KEY만 쓰면 됩니다 — 로컬이랑 이름이 같아서 동일한 식별자를 사용합니다.

cf-typegen은 Secret 등록 후 재실행할 필요가 없습니다. 타입은 이미 API_KEY로 정의되어 있고, Secret은 값만 Cloudflare에 저장합니다. 로컬: .dev.vars, 배포: secret put — 코드에서는 동일하게 env.API_KEY를 사용합니다.

5.6 CSP (Content Security Policy)

ChatGPT 앱의 위젯은 iframe 안에서 실행됩니다. 보안 때문에 기본적으로 아주 엄격하게 제한됩니다.

🚫 CSP 없이 iframe만 쓰면

  • CSS 파일 로드 불가 (스타일 깨짐)
  • JavaScript 실행·로드 제한
  • favicon 같은 리소스도 막힘
  • 외부 API fetch도 기본 차단

✅ _meta.ui.csp로 허용

  • 필요한 도메인만 화이트리스트
  • 위젯 HTML + 스타일 + 폰트 + TMDB 이미지
  • Workers API 호출 (connectDomains)
  • registerAppResource 응답에 넣으면 됨

위젯이 하얗게 보이거나 CSS가 전혀 안 먹으면, “코드 버그”보다 CSP에 도메인이 빠진 경우가 많아요. DevTools Network에서 막힌 URL을 보고 resourceDomains 또는 connectDomains에 추가하세요.

1 두 가지 도메인 목록

connectDomains

fetch, XHR 등 연결할 URL (API 호출)

  • https://*.workers.dev

resourceDomains

CSS, JS, 폰트, 이미지, favicon 등 불러오기

  • https://*.workers.dev
  • https://fonts.googleapis.com
  • https://fonts.gstatic.com
  • https://image.tmdb.org

2 registerAppResource에 넣기

src/index.ts — Movies Widget 리소스를 등록할 때 _meta.ui.csp를 이렇게 지정합니다.

registerAppResource(server, 'Movies Widget', WIDGET_URI, { description: 'Movies Widget' }, async () => {
  const html = await env.ASSETS.fetch(new URL('http://hello/index.html'));
  return {
    contents: [
      {
        uri: WIDGET_URI,
        text: await html.text(),
        mimeType: RESOURCE_MIME_TYPE,
        _meta: {
          ui: {
            csp: {
              connectDomains: ['https://*.workers.dev'],
              resourceDomains: [
                'https://*.workers.dev',
                'https://fonts.googleapis.com',
                'https://fonts.gstatic.com',
                'https://image.tmdb.org',
              ],
            },
          },
        },
      },
    ],
  };
});

동작 요약

  • env.ASSETS로 가져온 위젯 HTML이 iframe에 들어감
  • 그 HTML이 참조하는 CSS·폰트·이미지는 resourceDomains에 있는 곳만 로드됨
  • 영화 API·Worker 호출은 connectDomains에 맞는 주소만 fetch 가능
  • TMDB 포스터(image.tmdb.org)를 쓰려면 반드시 resourceDomains에 포함

새 CDN이나 API URL을 위젯에 추가할 때마다 CSP도 같이 업데이트하는 습관을 하세요. Secrets(5.3)는 “값”, CSP는 “어디서 불러올 수 있는지”를 정하는 입니다. 둘 다 위젯이 제대로 보이려면 필요합니다.

5.7 Dark Mode

위젯은 ChatGPT 같은 호스트 앱 iframe 안에서 실행됩니다. 사용자가 다크 모드를 쓰면 위젯도 동기화해야 합니다., 배경색을 고정하면 라이트/다크가 불일치합니다.

MCP Apps documentation에서 React 패키지 (@modelcontextprotocol/ext-apps/react)를 보면 useApp, useHostStyles, useHostStyleVariables, useHostFonts 등 포함된 함수·훅을 확인할 수 있습니다. ext-apps/react API 문서 →

1 useHostStyles

호스트가 보내준 CSS 변수, theme (light / dark), 폰트를 위젯에 적용합니다. 다크 모드는 theme: "dark"일 때 color-scheme와 변수가 바뀌면서 따라옵니다.

🌞 light

theme: "light"

🌙 dark

theme: "dark" — ChatGPT와 같은 톤

코드 위치: widgets/src/App.tsx. server는 HTML·CSP, UI·테마는 widgets.

import { useApp, useHostStyles } from "@modelcontextprotocol/ext-apps/react";

function App() {
  const { app } = useApp({
    appInfo: { name: "Movies Client", version: "1.0" },
    capabilities: {},
    onAppCreated: (app) => {
      app.ontoolresult = (result) => {
        if (result.structuredContent) {
          // tool 결과 처리 …
        }
      };
    },
  });

  useHostStyles(app, app?.getHostContext());

  return (
    <div className="items-center justify-center flex min-h-50">
      …
    </div>
  );
}

2 이렇게 하면 어떻게 되나요?

  1. ChatGPT가 host context를 보냄 (theme, styles.variables …).
  2. useHostStyles(app, app?.getHostContext()) — 연결 직후·테마 변경 시 다시 적용.
  3. document.documentElement에 --color-background-primary 등 CSS 변수 설정.
  4. theme: "dark" → color-scheme: dark, light-dark() CSS도 동작.
  5. 사용자가 ChatGPT를 다크 모드로 바꾸면 위젯도 같이 어두워짐.

문서에서 같이 보면 좋은 훅

  • useHostStyles — 변수 + 테마 + 폰트 (권장)
  • useHostStyleVariables — 색·테마만
  • useHostFonts — 폰트만

색은 var(--color-background-primary)처럼 호스트 변수를 사용하세요. 다크가 안 맞으면 useHostStyles 호출과 5.6 CSP를 함께 확인하세요.
